# Ghostlink 0.9.0 security and application review

Reviewed November 21, 2026. GitHub `main` and the published Windows x64 release both point to `d989fbce6c8a8a6ffbbf094aabe7a41bb50c5e9f`. Fix room admission and revocation first. A former participant can continue receiving pointer activity after the user creates a new room with a different secret. [Reviewed release](https://github.com/paavalipopov/ghostlink/releases/tag/v0.9.0)

## Development fixes, November 22, 2026

The published 0.9.0 installer still has the findings below. Both participants need the development build for the new pointer protocol.

- Disconnect closes the room's negotiating and established WebRTC connections. The new transport requires encrypted offer and answer signaling with the current secret and verifies both endpoints against the room and connection fingerprints. Pointer actions only target admitted peers. Test runs have their own protocol identifier. The secret field and dice stay locked until disconnect.
- A sharing room allows eight native connections in total, including pending negotiations. The private test room allows one. Each room has a 64 KiB transport receive budget. Relay traffic and raw data-channel frames are checked before protocol parsing. Pointer actions have a 1 KiB limit and separate movement and click rates per peer. Each room sends the overlay its latest coordinates at most once every 33 ms and retains the four newest click flashes per peer.
- The release builder uses read-only repository access. An isolated signer checks the origin of the tag and installer. A separate draft job verifies the signature, signed version and corresponding source. The GitHub environment `updater-signing` is restricted to the branch `main`. The owner must move the existing credentials into that environment and remove the old repository secrets before the next release. [Signing setup](tauri-prototype.md#signed-updates)

Local tests use three browser contexts, a loopback Nostr relay and real WebRTC data channels. They cover normal exchange, click expiry, a secret change with the former peer still running, a different password on the same discovery topic, simultaneous private testing and reconnect. Resource checks cover physical connection caps, allocation rate, frame and action limits, render batching and cancellation. A disposable signing key verifies the feed and installer, including rejection of a changed file and a mismatched signed version. Two physical PCs and a protected GitHub signing run remain release checks. The saved fullscreen selection and weak custom-code findings remain open.

## Findings in the published release

| High | [link.ts:115](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src/renderer/src/link.ts#L115) | **A replacement secret does not reliably revoke a former peer.** The released app still delegates room admission to Trystero 0.26.0. A previously connected peer can be admitted to a new room in the same running app without knowing its secret. The November 11 review demonstrated this in isolation. The shipping integration, relevant protocol source and dependency version still match. Require mutual proof for every room attachment before sending or accepting pointer data. |
| High | [link.ts:129](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src/renderer/src/link.ts#L129) | **Network work can exhaust memory or make the app unresponsive.** Eight is the displayed-pointer limit. Discovery can create pending connection work before admission, and incoming actions inherit a 256 MiB receive budget with no app-level rate limit. Bound pending and admitted connections, bytes before allocation, and incoming work across peers. Coalesce movement while preserving individual click feedback within its own rate limit. |

The same step invokes npm/Tauri and then the source packager. Build with read-only permissions, verify the release tag and artifact digest, and sign on a fresh protected runner using trusted tooling. [Build script](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/scripts/build-tauri-release.ps1#L29) |
| Medium | [App.tsx:463](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src/renderer/src/App.tsx#L463) | **The visible secret can differ from the active room.** Editing or rolling the code while waiting or connected updates the field and saved preference. The session keeps the secret captured when Connect was pressed, and current peers can continue receiving activity. Resolve a picked window again or require a new pick before sharing, including when reading old saved bounds of unknown origin. [Tracking event](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src-tauri/src/main.rs#L249) · [Restore](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src-tauri/src/main.rs#L201) |

An observer of the discovery topic can check guesses. Prefer a generated secret on first use and make an explicit product decision about short custom codes. The dice generator uses Web Crypto and has 100 bits of entropy. |

For people using 0.9.0 now, fully quit and reopen Ghostlink before generating a replacement secret with the dice. Share it only with the intended participants. After closing the app while fullscreen, pick the intended window again before pressing Connect.

The sharing-area and secret-field findings above follow the released source paths. The network findings carry forward the earlier isolated evidence. This pass used source inspection, ordinary tests and public advisory data. Live two-PC adversarial testing, fuzzing and a line-by-line audit of the third-party engines are outside its coverage.

## Work to prioritize

1. **Secure room membership and network limits together.** Evaluate Trystero 0.27.0, which was available in the npm registry at review time. It changes the handshake and event APIs and provides room and receive controls. Validate the integration before crediting it with a fix. Acceptance means that both participants prove the current secret, rotating or leaving ends old access, the private test room stays isolated, and peer counts, memory and render work stay bounded. Decide how older clients will be handled and verify ordinary two-PC reconnects. [Upstream migration guide](https://github.com/dmotz/trystero/blob/main/MIGRATION.md)
2. **Protect signing and make the UI match what is shared.** Restrict the key to the signing job before publishing the security update. Cover both secret controls and saved selection migration. A picked window should never silently become a larger input area after restart. Explicitly saved drag frames and displays should still restore. The panel also saves typed and generated secrets in WebView local storage. Consider opt-in “remember secret” or OS-protected storage if persistent secrets are needed on shared computers. [Storage](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src/renderer/src/App.tsx#L36) · [GitHub guidance](https://docs.github.com/en/actions/reference/security/secure-use)
3. **Fix the Windows capture fallback and finish game trials.** One fallback adds a taskbar window style. Windows can return zero on success, and the code then takes the error path before recording the need to restore the style. Forced helper termination can also skip normal restoration. Prefer capture without modifying the source window, or account for both the return value and cleanup. This finding comes from source inspection. Exercise the bundled release with Explorer, Telegram and a windowed game on two PCs. Check both exit shortcuts, guest alignment at the edges, clicks through the overlay, Alt-Tab, camera capture and reconnects. Earlier fixture trials covered click-through, emergency exit and forced cleanup on an ordinary window. Mixed display scaling remains deferred. [Capture fallback](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/third_party/magpie/src/Magpie.Core/GraphicsCaptureFrameSource.cpp#L253) · [Windows return contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongptrw#return-value)
4. **Run the first Linux/X11 VM trial.** Build and open the panel, verify transparency and click-through, then exchange a local WebRTC data-channel message in the actual webview. WebKitGTK 2.54 disables WebRTC, so the VM runtime determines whether a transport change is needed. Window picking, desktop click capture and the Magpie helper are Windows-specific. Fullscreen for a dragged rectangle or entire display also remains a separate feature on Windows. [Linux test guide](linux-vm-testing.md) · [WebKitGTK release notes](https://webkitgtk.org/2026/09/16/webkitgtk-2.54-highlights.html#multimedia-improvements)
5. **Make regressions visible before tagging.** The current workflow exercises Windows tests during release. Run the security and selection regressions on pull requests. Point the default development and build commands at Tauri so contributors using those commands exercise the shipped app. [Workflow triggers](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/.github/workflows/release.yml#L3) · [Package scripts](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/package.json#L25)

## Checks performed

- All 30 TypeScript tests and 21 Windows Rust tests passed. One separately marked Rust child fixture runs through its parent test. The published installer’s extracted app passed the isolated WebView2 checks for overlay placement, guest visibility, stale-session filtering and saved frame settings. These checks use synthetic pointer data.
- The public update feed, installer and signature matched the previously verified release bytes. All five GitHub asset digests matched. The existing updater public key verified the installer and its signed version. The fullscreen helper uses bounded inherited pipes, validates the chosen window identity and runs with the caller’s privileges. Peer input reaches an overlay that renders names as React text and coordinates as pointers. [Helper](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/native/fullscreen-host/host.cpp#L132) · [Peer overlay](https://github.com/paavalipopov/ghostlink/blob/v0.9.0/src/prototype/overlay.tsx#L99)
- npm reported zero advisories for production-classified dependencies. One moderate `minimatch` advisory accounts for all 12 flagged entries in the full development tree, through lint and packaging tools. [Advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249)
- OSV checked 457 Cargo packages, nine Conan runtime libraries plus CMake, two NuGet packages and the pinned Magpie commit. The matches were a GLib iterator advisory and maintenance notices for `chrono` and `proc-macro-error`. All three crates are absent from the Windows x64 Cargo tree, including build dependencies. Revisit GLib during Linux work. Advisory matching covers published records for those coordinates.
